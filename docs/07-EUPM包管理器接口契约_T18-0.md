## 一、定位与形态（三阶段）

| 阶段 | 形态 | 范围 |
|---|---|---|
| v1（V0.9.2 交付） | **App 内嵌页**（EUPackagesViewController） | 源管理/浏览/搜索/安装/卸载/升级——复用 bootstrap 内 procursus 的 apt+dpkg，**零自研包引擎** |
| v2（V1.0） | 独立 App（可选）+ eu-repo aptly 化 | 与 Sileo/Zebra 共存不互斥 |
| v3（长线） | 自研解析内核 | 仅当 apt 兼容性成为瓶颈（当前无此迹象） |

不重复造轮子的依据：bootstrap 内 /var/jb/bin/apt-get、dpkg 已由 roothide Procursus 镜像提供（B20）；apt 文本协议稳定 20+ 年，解析层薄。

## 二、后端接口契约（App ↔ bootstrap 工具链）

全部经 `runAsRoot:`+`runUnsandboxed:` 组合块（树内 EUEnvironmentManager 现成通道，jbctl/respring 同款）+posix_spawn 管道；**fd 进度协议**用 `apt-get -o APT::Status-Fd=<fd>`（apt 1.x 标准）。

| 操作 | 命令 | 输出协议 | 错误映射（用户文案级） |
|---|---|---|---|
| 刷新源 | `apt-get update` | Status-Fd 行流（dlstatus/pmstatus） | 网络失败=按源逐条（哪条源红一目了然）；GPG 失败=NOKEY code+URL；Release 过期=提示重刷 |
| 查询已装 | `dpkg -l` | 文本表（ii/rc 前缀+版本列） | 仅解析 ii 行 |
| 查询可用 | `apt-cache policy <pkg>` | 文本（Candidate/Installed 两行） | 候选缺失=源内无此包 |
| 搜索 | `apt-cache search <term>` | 文本（pkg — desc） | — |
| 安装/升级 | `apt-get install <pkg>=<ver> -y -o Dpkg::Options::=--force-confnew` | pmstatus 行流+dpkg 进度 | 依赖冲突=原样透出 apt 文案（不翻译术语）；dpkg 锁=「另一个包管理器正在运行」 |
| 卸载 | `apt-get remove <pkg> -y`（purge 单列按钮） | 同上 | 配置残留=提示 purge 可清 |
| 锁语义 | dpkg lock（/var/lib/dpkg/lock*） | flock 非阻塞探测 | 持锁=Sileo/Zebra/EUPM 三方任一在跑→前端禁用操作按钮（A 底座"双 PM 共存锁"扩展为三方） |

## 三、源管理契约（前端唯一写入口）

1. 读写 `/var/jb/etc/apt/sources.list.d/*.list`（与 Sileo 完全同格式——Sileo 写的 EUPM 认，反之亦然）。
2. **固定源**（PresetSources 三模式清单内的）：显示为锁定态（锁图标+不可删），与 ADR-R14 UF_IMMUTABLE 层一致——UI 不给删按钮即不会触发 EPERM 报错（防呆）。
3. **eu-repo 客户端**：Flat 结构（Suite=`./`）+ InRelease 内嵌签名优先/Release.gpg 分离签名回退（eu-repo 两件都有）；公钥分发=首次添加源时随 URL 引导下载 `euphoria-repo.pub.asc`+导入 keyring（apt-key 或 /etc/apt/trusted.gpg.d/ 投放）。
4. EU 源激活点：R17 域名定案 → PresetSources.plist 两处 EU 槽 URL 填入（rootless+roothide 双形态，eu-repo 架构过滤按模式出不同 Packages）→ EUPM 首刷即见（T18-d）。

## 四、分发与首装（T18-d）

1. **EUPM deb 双通道**：随 App bundle 内嵌（同 Sileo/Zebra 的 `Package`/`Display Name` 机制，installPackageManagers 循环内自然装入）+ eu-repo pool 同步发布（升级走源）。
2. 首装集成：finalizeBootstrap 现有 `installPackageManagers` 零改动兼容（EUSettingsController「重装包管理器」选择器加 EUPM 第三项，默认勾选）。
3. 升级判定复用 `shouldInstallPackage`+`numericalVersionRepresentation`（树内现成）。

## 五、验收边界（V0.9.2，防吹牛）

1. 装机后 Sileo/Zebra 正常共存（dpkg 锁互斥不 panic）；EUPM 可刷 eu-repo+当前模式全部预置源（红源逐条可见，不整页绿/整页红——对齐用户"源全红"的可见性诉求）。
2. 可安装/卸载一个真实包（首个测试件=巨魔E 安装器 deb，eu-repo pool 已有）。
3. 進度条三态（下载/解包/配置）走 fd 协议真实数据，非假进度。
4. 不支持的（如实标注）：v1 无截图画廊/无评论/无推荐流——那是商店功能不是包管理器。

## 七、风险与开放问题

1. apt 文本协议解析的健壮性（本地化输出）：后端 spawn 时强制 `LC_ALL=C`（A 底座坑位§一.1 同源结论）。
2. fd 进度协议在 posix_spawn 管道下的背压（长输出别死锁）：Status-Fd 指向独立 pipe，逐行读。
3. apt-key 弃用趋势（apt 2.4+）：trusted.gpg.d 投放为主路径，apt-key 仅回退。
4. EUPM deb 的 arm64e（roothide 模式）vs arm64（rootless 模式）双架构包：eu-repo 架构过滤已就位（A 建索引器时做了），App 侧按模式拉对应 arch 包。
