## 五 bis · 路径级拦截层（用户 08-29 17:00 终版语义：黑名单模式为主+全量可选档）

**语义演变记录**：11:46 用户初提"哪怕是文件管理器也不能知道 root"（无差别屏蔽）→ 17:00 收回（理由：文件管理器本身靠越狱/巨魔提权，属自己人）→ **终版=黑名单机制**："屏蔽软件是有黑名单的，用来拉黑软件，让他们检测不到越狱环境"；无差别隐藏"想做就做"=降为可选技术能力，不作产品要求。

实现规格：
1. **黑名单模式（默认，产品语义）**：路径拦截 interpose 全家桶（open/openat/stat/lstat/fstatat/access/faccessat/readdir/getattrlist/pathconf）命中屏蔽路径集返回 ENOENT（与"不存在"不可区分，防 EACCES 探测）——**仅对黑名单内 app 生效**（进程级判定：被拉黑 app 的进程树全部路径访问过滤镜）。**黑名单条目生效范围=路径 ENOENT+L3 遮蔽全套联动**（A 17:02 定向）：拉黑 app 同时启用 cs_flags 序列还原+AMFI 呈现+dylib 隐藏全套；默认放行 app 呈现真实状态（jbroot 随机化除外——随机化是全局设计属性非遮蔽层）。黑名单管理=App 设置页+aegis 现成底座（A 17:02 核：appBundleIds[]+appLevels[] 分级+defaultLevel=0 默认放行+XPC 序列化同步，**不新造机制**；roothide Bootstrap 同款 per-app 交互）。
2. **全量可选档（能力保留，默认关）**："想做就做"授权下实现同一拦截层的全 app 生效版本（高级设置项，默认关闭；文件管理器类自己人工具正常可见越狱文件）。
3. 屏蔽路径集：jbroot（随机化后）+/var/jb bind 之下全部+cloak cover mount 挂载点+aegis.c tell-tale 清单全集。
4. readdir 目录级过滤：被拉黑 app 列目录时屏蔽条目不出现（连"名字存在"都不给）。
5. 信任边界：launchdhook 系统层注入不经用户态路径访问（注入链不受影响）；jbctl/cloakd/aegisd 经进程信任标记（cloak_process_is_trusted 现有机制）绕过拦截。
6. 形态归属：路径屏蔽属"越狱存在"向量（L1）→Form-A/Form-B **两形态均启用**（黑名单判定与形态判定正交：形态决定遮什么向量，黑名单决定对谁遮）；L4 三字段仍 Form-B 专属。
