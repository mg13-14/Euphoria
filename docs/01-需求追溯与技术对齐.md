### ADR-009：fakefs 为 rootful 主路径（2026-08-26 00:28，A 深研报告+汇总员交叉验证）⚠️ supersedes ADR-002
- **触发**：用户 00:21 "rootful 死要求+禁用硬件漏洞" → A 00:28 深研报告《16~18.7.1 纯软件 rootful 技术可行性》→ 汇总员 00:29 交叉验证通过
- **核心结论**：iOS 16~18.7.1 (A12/A13) 上纯软件运行时 fakefs（真 rootful）**物理可行**，无需 kernel text patch、无需硬件漏洞
- **技术路径**（A 报告 §三，汇总员验证通过）：
  1. SSV 运行时校验 = 内核读路径 hash 校验，仅对带 `APFS_INCOMPAT_SEALED_VOLUME` 标志的卷生效（Apple Platform Security Guide secd698747c9）——**非硬件级密码学密封**（C 17:47"硬件级密封"判断有误，已纠正）
  2. fakefs 绕过 = 创建非 sealed 新 APFS 卷 → 复制原卷内容（读未篡改数据 hash 通过）→ remount 到新卷 → 新卷不触发 SSV 校验
  3. 核心操作 = VFS/APFS 数据结构修改（mount struct、APFS 元数据）= 内核**数据段**操作，在 KRW 范围内，**不需 kernel text patch**，不受 PPL 约束
  4. A12/A13 在 iOS 17/18 用 PPL（非 SPTM/TXM，那是 A15+），Dopamine 16+ 已有 PPL bypass + 内核 R/W → fakefs 前提条件成立
  5. 补充修正：A12/A13 可能根本无 PPL 硬件（PPL 是 A14+ 引入），若属实则更利好
- **参考实现**：Fugu15_Rootful（15.0-15.4.1 arm64e）、Dopamine_Rootful（15.x 全线 arm64e+15.0-15.8.6 arm64）、ghh-jb 的 APFSRW/Makerw/bootstrapfs 组件
- **A vs C 分歧裁定**（汇总员 00:31）：fakefs 是通用技术（A 论）而非依赖特定 SSV 缺陷（C 论）——Dopamine_Rootful 覆盖 15.x 全线含 15.5+ 支持通用路径论。以 A 通用路径为工作假说推进，C 的风险点（16+ APFS/mount 路径变化）纳入 B 逆向验证清单
- **B 执行指令**：rootful 主路径改为 fakefs（非 sealed 新卷+复制+remount），参考 ghh-jb 组件；nullfs 兜底保留作降级方案；16+ APFS/mount 路径逆向为关键风险项
- **置信度**：技术机制（§二~四）高置信（15 信源交叉验证）；16+ 可行性论证中高置信（物理约束不排斥，无公开先例但前提条件已具备）

### ADR-014：ghh-jb mount-over 式 rootful 参考实现入库 + "16+ 无路径"结论修正（2026-08-26 17:47，C7 交付 + 汇总员核验）
- **触发**：汇总员 17:29 派发 C 深析 ghh-jb/Dopamine_Rootful 源码（fakefs 调用链 + 16+ 移植风险）→ C7 于 17:44 落地（整库克隆逐行分析）
- **核心发现**：ghh 的 rootful 是 **mount-over 式**（非 F15R 的 snapshot-fake 式）——容器内新建 6 个普通 APFS 卷（/usr、/Library、/Applications、/private/etc、/sbin、/bin 整目录复制）后 `mount(MNT_FORCE)` 覆盖挂载，**不触碰密封快照**；SSV 校验点在启动早期，运行时挂载表操作不重验 → **16+ 理论上无需破解 SSV**
- **结论修正**：C 00:22~00:29 的"排除 bootrom 后 16+ 无软件级 rootful 路径"按 C7 §三口径修正——**F15R 式无路径成立；mount-over 式存在公开参考实现**（fork 自 opa334/Dopamine@2cfd690，主组件 bootstrapfs，APFS 私有 SPI 建卷 + jbclient_root_steal_ucred 提权），可行性待实机验证
- **双流程映射（R11）**：持久层=建卷+全量复制（首次，GB 级分钟级）；激活层=每次越狱 remount（秒级）——B 的 T14 双流程天然契合，文案区分"激活（首次）/恢复（历次）"；makerw（tmpfs 法）已弃用，仅留 commit/reapply 范式参考
- **三点实机验证项（转 A）**：①16+ 设备命名分支 disk1s%d/容器 disk1（代码已写、原作者未测，README 仅声明 15.x）②APFSVolumeCreate/Delete SPI 在 16/17/18 的符号存在性 ③17/18 PPL/SKM 下 mount 的 MAC 检查（mac_vnode_check_mount 可能拒绝非 System 角色卷）

- **文档动作**：05 规范 v1.1 §5.2 措辞同步（"根可写快照"→"根可写副本"，对齐 mount-over 口径）
