# A34 注入引擎 Mach-O 审计清单（审计位前置输入·B 主刀不受此约束）

> 交付人：并行搜索员A（Mach-O 层审计/核验位）｜日期：2026-09-07 21:25
> 用途：B 线注入引擎（ChOma 重签+insert_dylib 路）设计期参考+落地后审计基线。审计位只验不裁——实现取舍权在 B。

## 一、Header / Load Command 层

| # | 审计点 | 要点 |
|---|---|---|
| 1.1 | LC_LOAD_DYLIB 插入空间核算 | ncmds+1、sizeofcmds 增量精确；__TEXT header padding 足够（不足时的 resize 策略与后续 LC/section 偏移重排） |
| 1.2 | dylib path 形态 | @executable_path/... 相对路径（绝对路径=/var/jb 特征泄漏，越狱检测点）；path 长度+对齐 pad |
| 1.3 | 链接语义 | 强制 vs LC_LOAD_WEAK_DYLIB（失败降级策略与如实报错） |
| 1.4 | 与既有 LC_RPATH 交互 | 多 dylib 池注入时去重、顺序稳定性（重放表一致性） |

## 二、Code Signature 层（ChOma 侧）

| # | 审计点 | 要点 |
|---|---|---|
| 2.1 | CodeDirectory 重算覆盖 | 改动落在 __TEXT page0 → hash slot 0 必须重算；sizeofcmds 变更不得逃逸 |
| 2.2 | blob 结构完整 | SuperBlob 排布/identifier/entitlements blob 保持原样（不因注入降权原 app） |
| 2.3 | nested code 范围 | Frameworks/PlugIns/XPC 的处理边界（只注主二进制 or 按需递归——B 裁定，审计记台账） |
| 2.4 | 签名目标来源态 | 已装 AppStore 签（FairPlay DR）与侧载签两种输入的转换路径各自验证（TrollFools 先例：i_82 注入形态） |

## 三、dyld / AMFI 运行时层（越狱态引擎A 域）

| # | 审计点 | 要点 |
|---|---|---|
| 3.1 | closure 缓存重建 | dyld3+ closure 按主程序 mtime 失效——改后必须触发（touch/重写即达） |
| 3.2 | 注入 dylib 信任链入口 | 越狱态：trustcache 写入 or ldid 假签（与 B25-2 改码/rootify 路线口径对齐）；免越狱桩态：如实提示不假成功（C 已定桩态纪律） |
| 3.3 | Library Validation / restrict | 越狱态关断路径核对；restrict segment 目标 app 的特判 |
| 3.4 | uicache/Respring 刷新 | 注入后图标/注册表刷新钩子（设置页已有入口，联动验证） |

## 四、验证门禁（审计位工具链）

1. `otool -l` 核对 LC 位置/计数/对齐（1.1/1.2）
2. ChOma verify / `codesign --verify --deep` 签名一致性（2.x）
3. 启动冒烟：注入 0/N 个 dylib 行为一致性+目标 app 崩溃回归（3.x）
4. 台账：每次审计结果入 research/ 快件（沿用 rN 门禁纪律，零阻断才过）

## 五、边界与如实声明

- 本件是审计位前置输入，非实现规格；B 主刀的架构裁定（含 2.3/3.2 的选项）优先。
- 免越狱注入=CT 研究线关联域（A33 M5 复核项），本清单当前只覆盖越狱态主线。
- 出土先例：TrollFools（i_82）insert_dylib+重签路线已验证该攻击面成活性；T36 巨魔R 案（deb+AppSync）为生态旁证。
