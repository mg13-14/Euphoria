## 二、技术事实链（用户认知校准，须如实向用户呈现）

1. **root 权限 ≠ 系统盘可写**。完整漏洞链+安全绕过 → 内核 RW+root uid，正确。但 iOS 15+ 根卷是 **SSV（Sealed System Volume）**：APFS 密封快照（`APFS_INCOMPAT_SEALED_VOLUME`），boot 时校验 hash 树，运行时只读挂载。**root 用户对 / 的写入会被 mount 层拒绝**——这不是权限不够，是文件系统级封印。
2. **fakefs 存在的原因恰恰是绕过 SSV 的唯一公开可行法**：建非密封卷→复制内容→挂载切换。树内现状（rootful.c L186-205 自述）：主路径=fakefs（bootstrapfs 引擎），备选=remount+overlay。**用户禁的"伪根"=我们现有的主路径**。
3. 用户说的"100% root 用不着伪根"在 iOS ≤14.8（无 SSV）成立；15+ 需要额外解除 SSV 封印，这是与内核提权**并列的另一道墙**。

## 三、真根路线图（理论路径+里程碑）

**路线 A：内核 patch 解封（推荐验证）**
- 工具箱已在树内：`BaseBin/XPF/`（ChOma PatchFinder 框架，含 ppl/sptm_txm patch 能力——roothide 同款内核补丁框架，非 Dopamine 组件，"乙"裁定下可保留）
- 做法：内核 RW 后 patch 挂载逻辑（去 RDONLY flag + 绕过 SSV hash 树校验路径）→ 直接 remount 真根 RW。**内存零副本**（满足用户"不多占内存"）
- 风险：SSV 校验可能贯穿 VFS 读路径（不只是挂载时校验一次），patch 点未知；**公开生态无人发布过**，全部自研验证
- 里程碑：M1=单点 PoC（改一个 rootfs 文件的 inode flag 并成功写回+重启后不 panic）→ M2=稳定 remount → M3=产品化。M1 达成才升到 95%

**路线 B：放弃真根，如实标注**（保底）
- 保留 fakefs 但 UI 副标题明示"伪根（卷副本，占存储）"，让用户知情选择。违反用户禁令，仅作 M1 失败后的诚实降级选项

**自研漏洞授权"做不出来就用网上的"**：转 A 线（CVE 矩阵已就位）。当前 exploit 集（kfd/dmaFail）本来就是"网上的"，真根需求下 XPF 路线同样吃公开组件——合规。

## 四、三态联动规格（B 的设置页实现依据，单写者纪律下移交 B）

偏好键（均走 jbsettings XPC，与 rootfulUserEnabled 同通道）：
```
roothideUserEnabled  默认 NO
rootfulUserEnabled   默认 NO
```

状态机（用户原话逐条映射）：
| 用户操作 | 联动效果 |
|---|---|
| 开 rootful | **自动写 roothideUserEnabled=YES**（"选了它会自动给你选 roothide"）；rootful 开启的前提=roothide 已开或随开 |
| 关 roothide | **若 rootful 开着→强制写 rootfulUserEnabled=NO**（"关了 roothide 就不能开 rootful"），弹提示"rootful 依赖 roothide，已一并关闭" |
| 都关 | rootless（默认态，无任何隐藏栈） |

UI 细节：
- rootful 行副标题："包含 roothide 隐藏栈"（捆绑关系的可见性）
- roothide 行副标题（rootless 态）："应用无法检测越狱"（用户 10:27 语义）；rootful 态的 roothide 描述升级为"底层防护：应用无法检测系统能力变更"（用户 00:11 的分层语义）
- 矩阵外设备：rootful 灰置（现有 eutrolle_rootfulSupported 判定沿用）；roothide 全设备可用
- 越狱中切换 rootful 立即 jbctl rootful enable/disable（现有实现）+重越狱后按新状态机走（BaseBin main.m 分支已存在，仅需对齐三态判定：`rootful → rootful+roothide 栈`；`仅 roothide → roothide 栈`；`都无 → 纯 rootless`）

**BaseBin main.m 三态判定修正点**（B 侧）：现注释 L402-405 的二态语义（false→roothide 模式）已过时，须改三态：都关=纯 rootless（无隐藏栈）——与汇总员 10:40:47 对 isRoothideMode 的修正同源，但**联动约束在 App 侧 UI 层强制**（BaseBin 只读两个键的组合，不重复实现联动，防双源逻辑漂移）。

## 五、与"乙"裁定（基座重写）的关系

真根 rootful（路线 A）依赖内核 RW 层（自研漏洞线替换区）+XPF（保留区）——**与去同源化重写正好同向**：重写执行层时直接按三态+真根架构设计，避免 fakefs 遗留。建议 V0.9.2 起源码基线重组时把 rootful 后端标记为"重构区"，fakefs 引擎仅保留作 fallback 分支直到 M1 达标。
