## 一、逐条评审

### ① libarchive 解包 — 通过

**判定依据**：
1. `/usr/lib/libarchive.2.dylib` 在 iOS 实机随系统提供，且**位于 dyld shared cache**——Mobile Hacking Lab《Patch Diffing CVE-2025-5915: Heap Buffer Over-Read in libarchive》原文："libarchive... ships as part of iOS and macOS. On Apple platforms it lives in the dyld shared cache as **libarchive.2.dylib**"（2025 年文，覆盖 iOS 17/18 时代在位性）。
2. 历史在位性旁证：Needle（iOS 渗透框架）iOS 9/10 实机崩溃日志显示 `/usr/lib/libarchive.2.dylib arm64` 已加载——该库自早期 iOS 起持续在位，14–17 域无移除证据。
3. TrollStore 自身用同一套 `archive_read_new / archive_read_support_format_zip / archive_read_data_block` API（RootHelper/unarchive.m），但**静态链接自编译的 libarchive**（Makefile：`_LIBRARIES = archive` + brew 头文件路径）——原因仅为"公开 iOS SDK 不带 libarchive 头/链接库"，**不是系统无此库**。dlopen 按路径从 cache 解析是标准行为。
4. 所用符号集（archive_read_new 等）自 libarchive 早期起 ABI 稳定，实机版本 54.x 时代仍导出。

**附注（不判缺陷）**：dlopen 失败路径已有明确错误码兜底；建议保留。

### ② proc_ucred_update_content root 化 — 判修（iOS 17.0 域 live blocker）

**缺陷描述**（`BaseBin/libjailbreak/src/util.c:1083-1120`）：
- `__builtin_available(iOS 17.0, *)` 分支走 `target_proc_with_ucred` 协议：posix_spawn procPath 并传 `--fd 3 --uid … --ruid … --gid … --rgid … --groups …`，**子进程必须是 setuid-root 且实现了该 argv 协议、向 fd 3 回写的助手二进制**（Dopamine 语境 = launchdhook）。
- Engine B jailed 语境传入 `selfExec`（普通 sideload 应用二进制）：既不实现协议不写 fd 3，也无 setuid → 子进程只得 mobile ucred → `proc_copy_ucred` 把 mobile ucred 拷回自身 → `getuid()!=0` → sessionFail（错误 13）。零残留、无 panic（childPid==-1 有早退保护），**但 17.0 必死**。
- 17.0 在 Engine B 域内**可达**：域校验放行（B25/C24），且 DarkSword Info.plist `DPSupportedRanges 15.0–18.7.1` 覆盖 17.0 → ③步漏洞门槛拦不住 → 流程活到 ④步撞此墙。此缺陷是 live blocker，非理论项。

**附带调用侧 bug**：`EUTrollE.m:551` `gid_t rootGroups[1]` 传入期望 `gid_t groups[NGROUPS_MAX]` 的形参；17+ 分支 `target_proc_with_ucred` 遍历 `groupsStrings[0..15]` → **栈越界读（UB）**。修复：声明为 `gid_t rootGroups[NGROUPS_MAX] = {0}`。

**修复方案**（置信度高——≤16.6.1 域既有实践即 Dopamine 15–16 同款直写；17.0 可行性由本仓内核基础设施保证）：
- 不动 BaseBin 共享 util（越狱态仍需原 setuid-child 语义），在 EUTrollE.m 新增 `EUTrollEJailedRootify()`：iOS 17+ 时**直接复用 else 分支逻辑**——`proc_ucred()` 已支持 17+ 的 `proc_ro → ucred` 解引用（kernel.c:46-55），kwrite32 写 uid/svuid/svgid/groups[0] + 尾部 `task_tokens.audit_token` 四字补丁（util.c:1107-1117 原样）。≤16.x 维持现状（现调用即正确）。
- 前置 `cr_ref == 1` 检查：原地改共享 ucred 会污染共享者；非 1 直接失败保零残留。
- 小注：现 else 分支只写 `cr_groups[0]` 不动 `cr_ngroups`——root 语义（gid 0）够用，记为化妆级瑕疵即可。

### ③ MobileInstallationInstall — 推翻重做

**"TrollHelper 同构"不成立（源码级证伪）**：
1. TrollStore 全仓（含 TrollHelper/RootHelper/TrollStoreLite/Shared）`rg MobileInstallation` **零命中**——没有任何代码调用 MobileInstallationInstall。
2. TrollStore 真实安装链（逐行核读）：
   - `TSApplicationsManager.m:installApp` → `spawnRoot(RootHelper, @[(custom|installd), path])`；
   - **默认 custom 法**（RootHelper/main.m:868 起）：`MCMAppContainer containerWithIdentifier:createIfNecessary:` 建容器 → 拷贝 .app → 写 `_TrollStore` 标记 → `fixPermissionsOfAppBundle`（0755/0644）→ `registerPath`（uicache.m：经 LSApplicationWorkspace 注册字典——ApplicationType/Path/IsAdHocSigned/SignerIdentity"Apple iPhone OS Application Signing"/SignatureVersion 等）；
   - **备选 installd 法**（main.m:969-999）：`LSApplicationWorkspace installApplication:withOptions:`（LSInstallTypeKey=1、PackageType=Placeholder）做占位安装后覆盖。
3. AltStore 源码克隆对照：同样无 MobileInstallationInstall 调用。
4. 公开域**不存在任何 iOS 15–17 调用该 C API 的现代工程**——该 ABI 属 iOS ≤10 时代 installd 协议；15–17 上符号存在性与回调语义（Progress/Error 键协议）皆无公开验证路径。dlsym 成功 ≠ 语义兼容，此假设按铁律不进实现。

**替换方案**（置信度高，TrollStore 14.0–17.0 全域实证）：移植 RootHelper **custom 法为 in-process 实现**（Engine B 在该时点已 root，无需独立 RootHelper 二进制）：`MCMAppContainer containerWithIdentifier:createIfNecessary:` → bundle 拷贝 → 权限修正 → uicache registerPath 移植。CT 域本体永久档与会话档 trustcache 安装**共用**此机制（会话档 exec 合法性来自会话信任缓存条目，注册机制相同）。现 MIInstall 的回调竞态/30s 超时语义随之删除——同步拷贝+注册，无回调竞态面。
**注意**：此方案落地前提=➕节 entitlement 门禁有解（见下）。

### ④ helper 双槽位 + URL scheme — 通过

- 本地实证：`Application/Euphoria/Info.plist` CFBundleURLTypes 已声明 `euphoria-trolle`，与 EUTrollE.m:507 移交 URL 一致。
- helper=本体 .app 整拷 → 自动继承同 scheme → 本体被删后 URL 移交仍可达（持久化语义成立）；helper 用独立 bundle id（dev.euphoria.trolle.helper）避免身份冲突。
- role/engine 字段向后兼容（旧条目无字段时 Engine A 重放逻辑兼容）已按 B25 落地。
- 小注（不判缺陷）：本体+helper 双装=同一 scheme 双注册，LaunchServices 择一打开（轻微 UX 歧义）。TrollStore 本体与其 persistence helper 副本同样共存同 scheme，生态已验证可接受。

## 二、➕ 新发现：安装腿 entitlement 门禁（超出四决策范围，登记 v1.2 风险簿首位）

**问题**：RootHelper/entitlements.plist 携带整套安装腿通行证——`platform-application`、`no-sandbox`、`container-required=false`、`com.apple.private.security.container-manager`、`com.apple.private.MobileContainerManager.allowed`、`com.apple.private.coreservices.canmaplsdatabase`、`com.apple.lsapplicationworkspace.rebuildappdatabases`、`com.apple.private.mobileinstall.allowedSPI`(Install/Uninstall/…) 等。TrollStore 安装链每一步的授权来源是 **CT 永签注入的 entitlements，不是仅 root**：
- MCMAppContainer → containermanagerd XPC（查 container-manager/MobileContainerManager.allowed）；
- uicache 注册 → lsd（查 canmaplsdatabase 等）；
- LS placeholder → installd（查 MobileInstallationHelperService.*）。

Engine B 安装进程 = 普通 sideload 应用 + KRW root + audit_token 补丁，**没有这些 entitlements** → XPC 服务门槛可能拒收。公开生态无先例：TrollStore 全家 = 有 entitlements；越狱工具 = 有 AMFI 内核补丁。我们两条路都不占——这是 Engine B 区别于一切公开先例的真正空白点，**比四决策中任何一个都硬**。

**候选路线（按置信度排序）**：
- A. csflags 补 `CS_PLATFORM_BINARY`（proc_ro→csflags 单点 kwrite32，本仓已有 proc_csflags_update 基础设施）→ 实测各服务是否接受"平台二进制"身份替代具体 entitlement。置信度低-中，工程量小，**建议第一个 spike**。
- B. 内核态 entitlements 对象指针移植（把本进程的 entitlements OSObject 指针指向某个 entitled 系统进程的对象）→ 置信度中，工程量中，随内核结构版本敏感。
- C. 绕开 XPC：root 直建容器目录结构 + 直写 LaunchServices sqlite → 置信度低（脆、随版本漂移），仅作兜底研究。
- 实机是唯一裁决途径（模拟不可替代）——建议列为 V0.9.2 Engine B 最高优先级实验项，与 B27 双轨制并行成"第三轨：安装腿 spike"。
