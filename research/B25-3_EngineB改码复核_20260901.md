## §2 误报洗清：工具回显层"吞字符"假象（全群级教训）

复核过程中，通过 sed/diff 输出观察到疑似文本损坏：`[main` 显示为 `ain`、`[helperDir` 显示为 `elperDir`、`class])` 显示为 `class]])`，一度误判为 C 落码时的系统性文本损坏（编译阻断级）。

**码点级终审推翻该判断**：从 r3 包解出原文件，用 python 直接读取并打印十六进制码点：

- 866 行真实码点 `5b 68 65 6c 70 65 72 44 69 72` = `[helperDir`（完好，非 `elperDir`）
- 987 行真实码点 `5b 6d 61 69 6e 20 76 61 6c 75 65 46 6f 72 4b 65 79` = `[main valueForKey`（完好）
- 990/994 行 `[main addObject` / `[mainPath stringBy...` 均完好
- `class]])` 为嵌套消息表达式的合法闭括号序列（`[main isKindOfClass:[NSMutableArray class]]` 双层闭合 + if 条件 `)`）

**根因**：本环境 Bash 工具的**输出回显层会把 `[` + 小写字母的两字符序列吞掉**（`[m`、`[h` 消失，`[M`/`[`+引号 不受影响），疑似 markdown 链接语法预处理。文件本身从未损坏。

> 今后任何"文件文本损坏"的判断，必须以**码点级验证**（python 读文件打印 hex/长度/count）为准，禁止仅凭 sed/cat/diff/回显肉眼判定。此前若有过同类误判，一律需要复核洗清。

## §3 真实发现：Persistence Helper"第二槽位"无效（已修）

### 3.1 推演链

原实现在 engineB 安装流程尾部（⑥后）将本体 .app 完整复制到 `/var/containers/Bundle/Application/<UUID2>/` 并调用 `EUTrollePermasignInstall` 注册：

1. 副本与本体 **Info.plist 完全相同 → bundleID 相同**；
2. `EUTrollePermasignInstall` 内部 `MCMAppContainer containerWithIdentifier:createIfNecessary:existed:error:` **按 bundleID 寻址 → 返回的是本体的容器（UUID1）**，第二槽位从不产生独立容器；
3. 于是流程退化为：删除 UUID1 容器中刚装好的本体 .app → 把 UUID2 里的副本拷回 UUID1 → **净效果=本体重装一遍**；
4. UUID2 目录成为**游离垃圾**（未注册、无引用，违反零残留纪律）；
5. registry 里 helper 条目在函数内部 `saveEntries` 写入后，被 engineB 主流程 ⑦ 基于旧快照的 `saveEntries` **覆盖丢失**——最终 registry 无 helper 条目，纯白工；
6. 风险路径：步骤 3 的重拷若失败（磁盘满等），**刚装好的本体被删且未恢复**（marker 残留、registry 指向已删路径），需走完整重装自愈。

## §4 备案项（不阻塞发码，逐版跟进）

1. **custom 安装腿未做 entitlements 增强重签**：TrollStore 安装第三方 app 时会以 ldid 伪签注入全套特权 entitlements；当前实现装出的 app 维持原签名原权。V0.9.1 首装本体场景够用（本体构建期已带 entitlements），**V0.9.2+ 安装第三方 app 时需补**。
2. **注册字典不含 Entitlements 键**：TrollStore registerPath 会 dump 二进制 entitlements 进字典（LS 查询面）；当前从简。影响：设置/诊断类 API 查询不到权限元数据，运行时 AMFI 验证不受影响。
3. **PlugIns 子目录不注册**：若 .app 含 extension/widget 将不被 LS 注册。Euphoria 本体当前无 PlugIns，无实际影响；装第三方带插件 app 前需补插件注册循环。
4. **replayTrustCacheEntries 出清策略偏激进**：`jb_trustcache_add_cdhashes` 单次失败（如 XPC 瞬断）即出清该条目；幂等语义下可接受（重装即恢复），但可加单条重试。
