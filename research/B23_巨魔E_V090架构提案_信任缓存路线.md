## 1. 树内资产盘点（为什么 Tier A 不需要任何新漏洞）

| 原语 | 树内位置 | 巨魔E 用途 |
|---|---|---|
| 运行时信任缓存注入 | `libjailbreak/src/trustcache.c:225 jb_trustcache_add_cdhashes()`（jbserver XPC 通道，含 TXM 链表序处理） | 把 ldid 假签 IPA 的 CDHash 写进 AMFI 信任缓存 → 签名校验放行 |
| 信任缓存文件构建 | `trustcache_file_build_from_cdhashes()`（v1 格式） | 持久化批量条目（演进用） |
| CDHash 计算/代码签名解析 | ChOma（CSBlob/CodeDirectory 全套） | 从 IPA 主二进制直接取 CDHash |
| App 安装+uicache | EUBootstrapper 既有链（R15 PM 安装同款） | 装入 /var/jb/Applications + 图标 |
| 越狱链 | momentarius（PPL）+ ClearSword（26.x 双环已核） | 提供 KRW 时刻执行注入 |

**机制一句话**：越狱态下，巨魔E = "ldid 假签 → jb_trustcache_add_cdhashes(CDHash) → 装入 /var/jb/Applications"——AMFI 视该 CDHash 为 Apple 级信任（信任缓存条目与系统二进制同权），任意 entitlements 生效。这是社区成熟手法（jailbreak 态 permasign 标准路线），非新发明。

## 2. 分层交付口径（对 R19 四要件的覆盖矩阵）

## 3. 实现切分（可直接派工）

1. **巨魔E 核心**（新文件 EUTrollE/*）：IPA 解包 → ChOma 取 CDHash → `jb_trustcache_add_cdhashes` → ldid 假签重打包 → 安装到 /var/jb/Applications → uicache。（~1 人日量级，全部现成 API）
2. **CDHash 重放表**：巨魔E 已装 app 清单持久化（/var/jb 下 plist），每次越狱 finalizeBootstrap 后幂等重注入（与 R14 层2 同模式，代码范式现成）。
3. **EU PM 集成**（R17 挂钩）：PM"安装"入口支持 .ipa 类型分发到巨魔E 核心。
4. **Tier B 研究线**（B19-1 §5 候选方向）：无里程碑承诺，按"允许的失败=诚实报告"推进（SSOT 过程指令）。

## 4. 风险与边界

- 信任缓存条目 flags：v1 条目需正确 category（allow-run/allow-untrusted-node）——trustcache.c 现有条目构造已含，直接复用。
- entitlements 生效深度：部分特权（如 task_for_pid-0 级）在无根进程下仍受 macOS/iOS 策略限制，巨魔E 文档如实标注能力矩阵。
- 26.x PPL 侧对信任缓存注入的影响：momentarius 链已在用（basebin 自身上线即走此路），无新增面。
- 与 TrollStore 共存：isInstalledThroughTrollStore 分支已有，无冲突。
